# /azyboard-setup-mcp

O usuário quer configurar o servidor MCP do Azy Board no cliente de code agent em uso (OpenCode, Claude Code ou Codex), em Windows, Linux ou macOS. Siga o roteiro em `references/mcp-setup.md` e conduza a configuração passo a passo:

1. Descubra o **sistema operacional** e o **cliente**. O padrão é o MCP **remoto com OAuth**; API Key remota e **stdio** são alternativas **depreciadas**, só para clientes sem suporte a OAuth no MCP.
2. **OAuth (padrão)**: peça apenas a URL do MCP (ex.: `https://<instalação>/mcp`) ou, para fixar um projeto, a URL do MCP do projeto (`https://<instalação>/mcp/projects/<projectId>`). Registre só a URL, sem cabeçalho de credencial (Claude: `type: http` + `url`; OpenCode: `type: remote` + `url`, sem `oauth: false`; Codex: `[mcp_servers.azy-board]` + `url`). Ofereça a **conexão assistida por script** (`references/mcp-setup.md` → "Conexão assistida pelo agente"): entregue para o **terminal do usuário** `node <caminho>/connect-mcp.mjs --client <cliente> --url <url>` (Windows/PowerShell, Linux ou macOS). Depois oriente a autorizar no cliente (`/mcp` no Claude Code, `codex mcp login azy-board`, `opencode mcp auth azy-board`) e aprovar no navegador logado no Azy Board. Nenhum segredo é copiado.
3. **Alternativa depreciada — API Key remota**: avise da depreciação. Oriente a gerar a API Key em **Minha conta → Gerenciar API Keys**, uma por cliente/ambiente, copiada uma única vez. Use o script com `--api-key` (ele pergunta a chave no terminal) ou a configuração manual com o cabeçalho `Authorization`. Em texto use placeholders (`azb_sua_chave_aqui`); nunca peça a chave no chat.
4. **Alternativa depreciada — stdio**: avise da depreciação; confirme Bun instalado e o caminho do repositório (ou `apps/mcp/dist/index.js`); monte a configuração com `EASYBOARD_API_KEY`, `EASYBOARD_URL` e, quando o repositório for de um único projeto, `AZYBOARD_PROJECT_ID`.
5. **Projeto no remoto**: use a URL do MCP do projeto (`/mcp/projects/<projectId>`), o argumento `projectId` ou, com API Key, o cabeçalho `X-Azyboard-Project-Id`; não existe `AZYBOARD_PROJECT_ID` no modo remoto e o projeto nunca vem da credencial.
6. Reforce a segurança: com OAuth não há segredo no arquivo; a conexão é revogada em **Minha conta → Conexões MCP**. Com API Key, a chave nunca vai em arquivo versionado, chat ou linha de comando; o `projectId` não é segredo, a chave é (o script avisa se o destino for versionado).
7. Verifique recarregando o cliente e confirmando `list_tasks`/`list_modules`, então execute `list_modules` para um projeto acessível. Se você já tiver acesso MCP na sessão, faça a verificação você mesmo.
8. Se houver erro, use a tabela de problemas comuns do roteiro (401, 403, 404, falha de conexão, OAuth não suportado).

A conexão remota pode ser feita pelo agente **com ação do usuário no terminal e no navegador**: gere/oriente o comando, peça que ele o execute e autorize, e depois confirme a conexão. Não invente hosts, caminhos ou credenciais.
