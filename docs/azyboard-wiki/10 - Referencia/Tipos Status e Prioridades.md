# Tipos, Status e Prioridades

## Tipos de item

| Tipo | Uso principal |
|---|---|
| Épico | Organizar um objetivo amplo dentro de um módulo e formar uma swimlane. |
| História | Descrever uma necessidade funcional e seus critérios de aceitação. |
| Task | Representar trabalho operacional ou técnico. |
| Bug | Representar um defeito que precisa ser investigado e corrigido. |
| Subtask | Dividir uma task ou bug em partes menores; tecnicamente continua sendo task ou bug. |

## Status de item

| Status | Significado |
|---|---|
| Não iniciada | O trabalho ainda não começou. |
| Em andamento | O item está sendo executado. |
| Bloqueada | Existe um impedimento para continuar. |
| Concluída | O resultado esperado foi entregue. |
| Cancelada | O item não será mais executado. |
| Arquivada | O item foi retirado das visualizações ativas, mas pode ser restaurado. |

## Status base de coluna

Cada coluna representa uma etapa do fluxo e possui um status base. Ao mover um card para outra coluna, o item assume o status base da coluna de destino.

Uma coluna pode representar os estados: não iniciada, em andamento, bloqueada, concluída ou cancelada. O arquivamento não é uma coluna, mas um ciclo de vida separado.

## Prioridades

| Prioridade | Uso sugerido |
|---|---|
| Baixa | Trabalho com pouca urgência ou impacto limitado. |
| Média | Prioridade padrão para trabalho regular. |
| Alta | Trabalho relevante que exige atenção antecipada. |
| Crítica | Trabalho urgente ou com alto impacto operacional. |

## Status de sprint

| Status | Significado |
|---|---|
| Planejada | Sprint preparada, mas ainda não iniciada. |
| Ativa | Sprint corrente do projeto. |
| Concluída | Sprint encerrada. |

## Status de versão

| Status | Significado |
|---|---|
| Planejada | Entrega definida, ainda fora de desenvolvimento. |
| Em desenvolvimento | Entrega em preparação. |
| Lançada | Entrega disponibilizada. |
| Cancelada | Entrega descontinuada. |
